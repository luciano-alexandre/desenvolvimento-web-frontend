# Disciplina: Desenvolvimento Web Frontend (60h)

Material didático da disciplina de **Desenvolvimento Web Frontend**, oferecida como continuidade de **Padrões Web** no Curso Superior de Tecnologia em Sistemas para Internet.

A disciplina parte da base de HTML5, CSS responsivo, acessibilidade e Git para avançar na construção de interfaces com **Tailwind CSS**, programação com **JavaScript/TypeScript** e desenvolvimento de aplicações com **Angular**.

## Identificação do Curso

- **Turma:** Graduação
- **Curso:** Tecnologia em Sistemas para Internet
- **Instituição:** IFRN — Campus Currais Novos
- **Carga horária:** 60 horas
- **Organização:** 80 aulas de 45 minutos, distribuídas em 40 encontros de 1,5h
- **Professor:** Luciano Alexandre de Farias Silva
- **Pré-requisito recomendado:** Padrões Web ou conhecimentos equivalentes de HTML, CSS e Git

## Objetivo Geral

Desenvolver competências para projetar, implementar, testar e publicar aplicações frontend modernas, responsivas e acessíveis, utilizando Tailwind CSS, TypeScript e Angular de maneira crítica e integrada.

## Percurso Formativo

1. revisão técnica dos conhecimentos de Padrões Web;
2. interfaces utility-first com Tailwind CSS;
3. transição de JavaScript moderno para TypeScript;
4. aplicações componentizadas com Angular;
5. integração com APIs e gerenciamento de estado;
6. testes, otimização, publicação e apresentação do projeto final.

## Avaliação

- **Unidade 1:** três atividades práticas de 20 pontos e um estudo de caso de 40 pontos, totalizando 100 pontos.
- **Unidade 2:** Projeto Final valendo 100 pontos, com dois encontros de acompanhamento e quatro encontros de apresentação.

Os instrumentos, marcos e critérios estão detalhados no [cronograma](docs/01-cronograma-60h.md).

## Como Utilizar este Repositório

Os estudantes devem começar pela visão geral e pelo cronograma. As atividades práticas devem ser versionadas em repositório próprio, com commits que representem a evolução real do trabalho.

## Princípios da Disciplina

- compreender antes de abstrair;
- construir em pequenas etapas verificáveis;
- tratar acessibilidade e responsividade como requisitos;
- usar frameworks com consciência técnica;
- separar responsabilidades e favorecer manutenção;
- testar estados de sucesso, vazio, carregamento e erro;
- documentar e comunicar decisões de projeto.
